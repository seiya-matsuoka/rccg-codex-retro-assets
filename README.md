# RCCG Codex Retro Assets

[Random Cool Color Generator](https://github.com/seiya-matsuoka/random-cool-color-generator) の Codex による開発を振り返り、今後の個人開発・技術学習で再利用する候補をまとめたリポジトリである。
初版作成日は 2026-11-05 とする。
過去の Web アプリ、CLI、ゲーム、言語・環境・テスト技術の学習成果物も参考にした。

必要なものを対象リポジトリに合わせて選択・調整し、次回の実践で有用性を確かめるための初版である。
共通設定の恒久的な標準化や、振り返りの詳細・開発ログの保存は目的に含めない。

## 成果物の一覧

AGENTS.md テンプレートは継続的な制約、プロンプトは今回の依頼、Skill は反復作業の手順、README は選択と利用の案内を担当する。
「実績を反映」は元の開発で得た原則を指し、ここにある新しいファイルの運用効果が確認済みという意味ではない。
全成果物は未適用・実運用未検証である。

学習支援プロンプトは、教材を作る役割と学習者が理解する役割を切り替えるために使用する。

## 用途に応じた選び方

最初に開始・再開プロンプトを使い、必要な成果物だけ追加する。
すべてを一括で読み込んだり、配置したりする必要はない。

| 用途                                     | 基本の選択                                                             | 必要に応じて追加するもの                                                   |
| ---------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 小規模な個人開発                         | 開始・再開、作業単位の実施                                             | 固有ルールが必要ならアプリ向けテンプレート、重要な境界のレビュー、文書整備 |
| 複数画面・業務処理・データ更新がある開発 | 開始・再開で全体構造と作業境界を整理し、機能ごとに作業単位の実施を使う | API・DB・状態遷移のレビュー、設計・仕様の文書整備                          |
| 技術学習                                 | 開始・再開で目標・学び方・教材の正本を確認する                         | 学習向けテンプレート、教材作成 Skill、教材レビュー、学習支援               |

Plan Mode は重要な仕様・構成・作業境界を決める場面で使用し、合意範囲内の実装・検証・原因修正はまとめて任せる。
Git の分担、文書の保存方法、README の作成時期、Unit の工程分離は対象リポジトリの合意を優先する。
特定の技術構成、検証コマンド、モデル、並列化を標準として固定しない。

## 次のリポジトリでの使い方

1. この保管先と対象リポジトリを参照できる状態にし、両方の絶対パスと目的を Codex に伝える。
2. この README と開始・再開プロンプトを読ませ、対象の現状、既存ルール、必要な成果物、調整案を読み取り専用で確認する。
3. 内容が揃ったら、今回の作業範囲を依頼する。
   テンプレートの配置や Skill のインストールが必要なら、対象・差分・配置先を示した具体案への明示的な依頼を別に行う。
4. 使用後は既存のチャット・Issue・学習記録で、説明の繰り返し、手戻り、調整の負担、残った課題を確認する。
   必要な修正だけをこの保管先へ反映し、役立たないものは採用しない。

開始時は、例えば次のように依頼する。
`{{...}}` は利用者が具体化する入力の目印であり、そのまま実パスや操作許可として扱わない。

```text
再利用用成果物の保管先：{{保管用リポジトリの絶対パス}}
対象リポジトリ：{{作業対象の絶対パス。未作成なら予定先}}
目的：{{今回作りたいもの／学びたいこと／再開したい作業}}
保管先の README.md と prompts/start-project.md を読み、その依頼本文で調査・提案してください。
対象の変更や成果物の配置・インストールは、まだ行わないでください。
```

プロンプトは依頼本文を貼り付けるか、絶対パスを指定して参照する。
分かっている情報の再入力や、すべての欄への記入は不要である。
AGENTS.md テンプレートは利用メモと配置用本文を区分している。
配置時は本文を調整し、未記入項目と不要な項目を除き、既存ファイルに必要な条項だけ統合する。
アプリ向け・学習向けの一方を基礎に選び、重複して配置しない。

## 保管と有効化の区別

標準の検出設定では、`templates/agents/app.md` と `learning.md` は AGENTS.md として適用されない。
`skills/` は、この保管先では通常のディレクトリとして使用する。
Skill の検出先である `.agents/skills/` やユーザーの Skills ディレクトリへの配置・リンクは行っていない。
独自の検出設定や既存の登録がある環境では、利用前にその状態も確認する。
[AGENTS.md の公式仕様](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[Skills の公式仕様](https://learn.chatgpt.com/docs/build-skills)を参照する。

保管中の Skill を試す場合は、ファイルの絶対パスを示し、手順として読んで指定作業へ使うよう依頼できる。
名前による選択や自動選択を試す場合は、利用環境の検出先、既存の同名・類似 Skill、適用範囲を確認してから、明示的な依頼に基づいて配置する。
この初版は、自動選択を無効にする設定や自動インストール処理を持たない。

既存のグローバル・プロジェクト AGENTS.md、Skills、Codex 設定を置き換えるものではない。
プロンプトや Skill の参照も、権限の拡大、外部操作、Git・GitHub の状態変更を許可しない。
各作業の明示的な依頼と、適用される制約に従う。

## 試行範囲と改善

初版の確認範囲は、形式・リンク・成果物間の整合性と、具体的な利用例への机上の適用確認である。
公式 Skill validator は、実行環境の PyYAML 不足により検証本体を実行できていない。
インストール後の検出・自動選択、実開発での効率や学習効果は未検証である。
形式確認を、実運用での有効性の証明として扱わない。

次の利用では、目的やルールを説明し直す負担、仕様の見落とし、文書の作り直し、範囲外の作業を減らせたかを確認する。
学習では、教材の生成済み・検証済みと、学習者の説明・作業・申告で確認できる学習済みを分ける。
作業規模や習熟度が異なるため、時間だけで効果を断定しない。
通常のチャットで十分なら、Skill や追加ルールを維持する必要はない。
