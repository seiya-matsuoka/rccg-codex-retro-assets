# 個人開発向け AGENTS.md テンプレート

## 利用メモ

対象リポジトリの継続的な制約を整えるための雛形である。
このファイル名のまま保管し、以下の本文を実際の `AGENTS.md` へ適応する場合は、配置先と差分への明示的な依頼を受ける。
既存の AGENTS.md がある場合は全文を置換せず、必要な条項だけ統合する。

- `{{...}}` は調整項目である。
  現物を確認して具体化し、不要な項目は削除する。
  未記入の欄やこの利用メモを、有効な AGENTS.md へ残さない。
- グローバル方針の全文を複製せず、このリポジトリで判断が変わる事項を残す。
- 新規で未確定の構成やコマンドは、合意・導入されるまで実在すると記載しない。
- 学習用途が中心なら、学習向けテンプレートを基礎にする。
  2 種類を重ねて配置する必要はない。
- 進捗・実行結果は既存の Issue や運用文書で管理し、本文には参照先だけ置く。

## 配置用本文

```markdown
# プロジェクト開発方針

本書は {{プロジェクト名}} に固有の作業方針を定める。
ユーザーの明示的な依頼と、適用されるグローバル方針を確認して使用する。

## 対象と制約

- 作業対象：{{対象のディレクトリ・構成単位}}。
- 目的・主な利用者：{{目的と想定する使われ方}}。
- 技術構成と導入済みツール：{{確認できた構成}}。
- 変更範囲の境界：{{対象外の機能、参考リポジトリ、保護するデータなど}}。
- 仕様上の制約：{{保存、通信、認証、対応環境など、実装判断に必要な事項}}。

## 参照先と文書

- 現行仕様・重要な設計判断：{{正となる文書とその役割}}。
- 作業計画・合意した変更：{{既存の計画・Issue など}}。
- 文書の更新方法：{{固定する計画と更新する文書の区別。区別がなければ実際の方針}}。
- 進捗・課題・検証結果：{{既存の記録先}}。

計画、現行仕様、実行記録を区別する。
重要な矛盾があれば合意済みの変更か確認し、現在の依頼範囲に関係しない履歴の整備を始めない。

## 実装と作業単位

- {{責務の分け方、境界、既存の設計上の不変条件}}を維持する。
- 依頼された作業単位の中で実装・検証・原因修正を行い、次工程へ進む条件は{{このプロジェクトの確認タイミング}}に従う。
- 学習目的がある場合のコード・テストコメントは{{説明対象と粒度}}に合わせる。
  責務、仕様との対応、採用理由、失敗時の扱い、テスト条件の意味を理解できる説明を残す。

## 検証

- 通常の変更に使う手順：{{実在するコマンド、実行ディレクトリ、何を確認するか}}。
- 追加確認が必要な変更：{{UI、非同期、保存、API・DB などと対応する既存手順}}。
- 実行環境・データ：{{テスト用状態、出力先、必要なサービス、操作の条件}}。

変更した振る舞いと関係する境界を確認する。
実行していない検証や、ローカルで確認しただけの CI・公開環境を完了扱いにしない。

## Git・GitHub と外部反映

- 人間と Codex の分担：{{操作ごとの担当。未決定なら状態変更は明示依頼後とする}}。
- 命名・commit・PR・merge のルール：{{既存ルールへの参照。未定義なら架空の慣習を追加しない}}。
- 公開・永続環境に影響する条件：{{デプロイの契機、DB の扱いなど。該当しなければ削除}}。

文案の作成と実操作を区別し、ある操作の許可を後続操作へ拡張しない。
```
