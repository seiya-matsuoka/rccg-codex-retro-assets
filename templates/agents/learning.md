# 技術学習向け AGENTS.md テンプレート

## 利用メモ

教材の品質と、人間の理解・技術習得の両方を重視するリポジトリに使用する。
このファイル自体は有効な AGENTS.md として配置しない。
本文の配置・統合は、対象と差分への明示的な依頼後に行う。

- `{{...}}` をカリキュラム、運用文書、既存教材から具体化する。
  未記入項目、不要な項目、この利用メモは配置用本文から除く。
- アプリ向けテンプレートと共通する事項は統合し、同じルールを重複配置しない。
- 説明の粒度は実際の教材や短い記述例で合わせる。
  一律の行数制限や、すべての Unit で同じ演習・ツールを使う規則は追加しない。
- Unit 単位、README の分離、共通サンプルの育て方は既存の運用を採用する。
- 生成・検証・学習の進捗は既存の記録先で管理し、本書には変動する完了状況を持たせない。

## 配置用本文

```markdown
# 学習リポジトリの作業方針

本書は {{学習リポジトリ名}} に固有の教材作成・学習支援の方針を定める。
ユーザーの明示的な依頼と、適用されるグローバル方針を確認して使用する。

## 学習目標と参照先

- 到達目標・対象者・前提知識：{{目標と前提}}。
- 学習方法：{{コードリーディング、操作の観察、演習など、合意した方法}}。
- カリキュラム：{{正となる文書}}。
- 教材仕様・共通サンプル：{{仕様と正本の場所}}。
- 作成・学習の運用：{{工程、README の扱い、確認タイミングを定める文書}}。
- 生成・検証・学習の進捗と課題：{{既存の記録先}}。

資料の役割と現在の合意を確認する。
古い引き継ぎや計画の進捗が現物と異なる場合は、その違いを示す。
重要な矛盾を、教材の存在だけで解消したことにしない。

## Unit の範囲と構成

- 作業単位と停止条件：{{Unit、教材生成・レビュー・README などの依頼単位と確認タイミング}}。
- 配置方針：{{共通サンプル、Unit ごとの独立例、補助教材の使い分け}}。
- 共通サンプル・過去 Unit を変更できる条件：{{明示的な対象と合意が必要な範囲}}。

指定 Unit や工程の完了後に、次の教材生成・依存導入・README 作成を自動で始めない。
後続のテストや説明に合わせるためだけに、共通サンプルや過去 Unit を無断変更しない。
段階ごとの独立性や比較に必要な重複を、一括リファクタリングで失わない。

## コード・解説・コメント

- 標準とする教材：{{粒度を合わせる既存 Unit または合意した記述例}}。
- コードと解説の構成：{{必須の説明、コメント、実行結果、注意点など}}。

概念、仕組み、具体的なコードでの役割、採用理由を結び付けて説明する。
通常のコードとテストの両方に、責務、入出力、前提条件、失敗時の扱い、Fixture・置き換え・Assertion の意味を、学習対象に応じて説明する。
型検査と実行時の動作を区別し、実装していない保証をコメントに書かない。
README とコメントの役割を補完させ、重要な説明を重複回避だけの理由で省かない。
完成コードを読む運用に、未完成の TODO や穴埋めを無断で導入しない。
説明用のアプリを、学習対象に必要な範囲を超えて複雑にしない。

## 検証と意図的な失敗

- 使用する検証：{{既存の実行・型検査・テスト・静的解析と、その学習上の役割}}。
- 観察対象：{{出力、終了コード、ファイル、HTTP、DB、複数セッションなど}}。
- 実行環境・出力先・操作の条件：{{独立した学習環境、データ、必要な許可}}。
- 意図的な失敗例の位置と扱い：{{実行方法、期待する失敗、通常の検証からの分離など}}。

予測する結果と、実際に観察した結果を区別する。
意図的な失敗を通常の不具合として修正せず、失敗する条件・理由・改善後の違いを説明する。
期待と異なる失敗は、教材の不整合として調査する。
実行できない環境条件や未実施の確認を示す。

## 学習者の作業と進捗

教材を作成・検証する役割と、学習者に理解を支援する役割を区別する。
コードリーディングでは十分な説明を提供し、演習では求められる前に解答や修正を完成させない。
練習による変更は{{許可された練習対象。未設定なら変更前に確認}}に限定する。
生成済み、検証済み、学習済みを別に扱い、学習済みは本人の説明・作業・申告で確認できた範囲だけ記録する。
Git・GitHub の分担は{{既存の運用への参照または操作ごとの担当}}に従う。
```
