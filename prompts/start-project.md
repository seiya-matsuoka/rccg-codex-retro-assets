# 開発・学習を開始／再開するためのプロンプト

新規開始または既存作業の再開時に、現状の調査と進め方の提案に使用する。
以下の依頼本文をチャットへ貼り付けるか、ファイルの絶対パスを示して参照を依頼する。
`{{...}}` は入力の目印であり、分かる項目だけ具体化する。
会話や資料から分かる内容は再入力しなくてよい。

## 依頼本文

```markdown
対象リポジトリを調査し、今回の目的に合う進め方と、必要な再利用用成果物を提案してください。
この依頼は読み取り専用です。
ファイル作成・編集、設定変更、成果物の配置・インストール、Git・GitHub の状態変更は行わないでください。

### 対象と目的

- 対象リポジトリ：{{絶対パス。新規の場合は予定先}}
- 目的：{{作りたいもの／学びたいこと／再開したい作業}}
- 再利用用成果物の保管先：{{この保管用リポジトリの絶対パス。使用する場合だけ指定}}
- 既知の制約・参照先：{{変更できる範囲、学習目的、関連資料など。既存情報で足りれば省略}}

### 調査すること

1. 作業先と参考資料の範囲を区別し、現在のディレクトリ、Git のルート、branch、未コミット変更を確認してください。
   まだ存在しない予定先を、作成・初期化済みとは扱わないでください。
2. 適用されるグローバル・プロジェクト・対象ディレクトリの指示と、README、計画、仕様、設定、関連コードを必要な範囲で確認してください。
   古い引き継ぎや計画と、現在の仕様・進捗を区別してください。
   読めない資料や、参照できない過去チャットの範囲を示してください。
3. 目的、利用者または学習者、到達点、重要な制約を整理してください。
   不明点のうち、既存情報で解決できるものは調査してください。
   結果を大きく左右する判断だけを質問し、軽微な事項は理由を添えて仮定してください。
4. manifest、設定、既存 scripts から、実在する検証方法と実行条件を確認してください。
   計画上のコマンドを実在すると仮定せず、外部通信、依存取得、サーバー・DB・コンテナ、永続データへの影響を区別してください。
   この調査では実行を伴う検証や環境構築を始めず、候補と必要条件を示してください。
5. 再利用用成果物を使う場合は、保管先の README を読み、今回必要なファイルだけ選んでください。
   すべてのプロンプト・テンプレート・Skill を一括で読み込んだり、採用したりする必要はありません。

### 進め方の選択

- 小規模開発は、短い要件と確認可能な作業単位を中心にしてください。
  独立した計画書や工程を、不必要に増やさないでください。
- 複数の画面・業務処理・データ更新がある開発は、全体構造と依存関係を整理し、利用者の操作と受け入れ条件で作業を分けてください。
  実装と検証を、技術層ごとに最後まで分離しないでください。
- 学習用途は、到達目標、前提知識、教材作成の範囲、学習者自身が行うことを区別してください。
  既存のカリキュラム、解説の粒度、Unit の構成、工程の確認タイミングを尊重してください。
- Plan Mode は、仕様・構成・作業境界の重要な判断に使う候補としてください。
  合意済みの小さな修正まで、毎回計画を作り直す前提にしないでください。

### AGENTS.md と成果物の適応

AGENTS.md は現物を読んで、今回必要な差分だけ提案してください。
継続的なリポジトリ固有ルールを AGENTS.md、今回の範囲を依頼文、反復手順を Skill、進捗を既存の Issue や運用文書に分けてください。
グローバル AGENTS.md の全文コピーや、一度きりの作業指示の常設化は不要です。
差分が不要なら、その判断を示してください。

合意した範囲の実装・検証・修正を任せられるか、既に与えられた許可を重ねて確認していないかも確認してください。
承認対象や保護対象を減らす変更は、単なる文章整理に含めないでください。

配置を提案する場合は、採用理由、対象ファイル、配置先、調整内容、既存の同名・類似ルールとの関係を示してください。
未記入のテンプレートや、保管用ファイルをそのまま有効化しないでください。
設定変更やインストールは、具体案への別の明示的な依頼を必要とします。

### 出力

1. 確認できた現状、資料の役割、参照できなかった範囲。
2. 目的・到達点と、判断が必要な重要事項。
3. 今回の作業単位、完了条件、検証方法、人間と Codex の分担。
4. 採用する再利用用成果物と調整案。不要なものは増やさない理由。
5. 次の作業を依頼するための短い文案と、必要な許可。

Git の分担・命名・merge 方法、文書の保存方法、README の作成時期は、対象リポジトリの合意を優先してください。
この調査の終了後に、実装や次工程を自動で開始しないでください。
```
