# 合意した作業単位を実施するためのプロンプト

1 つの機能、修正、文書作成、学習 Unit の指定工程などを、検証・修正・報告まで任せる場合に使用する。
以下の依頼本文を貼り付けるか、ファイルの絶対パスを示して参照を依頼する。
`{{...}}` は入力の目印であり、既存の計画や会話で合意済みの項目は参照で代用できる。
範囲を再利用する際も、以前の外部操作の許可を別作業へ持ち越さない。

## 依頼本文

````markdown
以下の合意した作業単位を実施してください。
範囲内の実装・検証・原因修正・必要な文書更新・完了報告までをまとめて依頼します。

### 作業の条件

- 作業先：{{対象リポジトリの絶対パス}}
- 目的・作業単位：{{機能、修正、文書、Unit と今回の工程など}}
- 変更を許可する範囲：{{対象と対象外。関連箇所の修正を含むかも明示}}
- 正となる参照先：{{仕様、計画、Issue、カリキュラム、合意したチャットなど}}
- 受け入れ条件：{{確認できる振る舞い、文書の役割、教材の到達点など}}
- 検証：{{指定手順。未指定なら既存設定から適切なものを選ぶ}}
- 特別に許可した操作：{{対象・操作・条件を明示。なければ「追加なし」}}
- 今回の終了地点：{{今回で止める工程。次のフェーズや Unit は含めない}}

### 実施方針

1. 作業先、branch、git status、適用ルール、関連する実装・文書・設定を確認してください。
   既存の未コミット変更と今回の変更を区別してください。
   重要な矛盾がある場合は、正となる判断を確認してください。
2. 受け入れ条件を満たす最小限の変更を行ってください。
   合意済みの通常の実装判断は自律的に進め、範囲内の検証失敗は原因を調べて修正してください。
   同じ対象・同じ操作について既に与えられた有効な許可を、理由なく確認し直さないでください。
3. 仕様変更、依存追加、許可外の外部操作、対象外の変更が必要な場合は、具体的な対象と理由を示して確認してください。
   技術選定や利用ツールの記載だけを、取得・起動・公開・データ更新の許可として扱わないでください。
4. 文書更新は今回の変更に必要で、かつ許可された範囲に留めてください。
   記録として固定された計画、別工程の README、過去 Unit、AGENTS.md や実設定を独断で更新しないでください。
5. Subagents や並行作業をこの依頼だけで自動的に開始せず、適用される指示と明示的な依頼範囲に従ってください。

### 検証と修正

実在する scripts・設定・既存手順から、変更に合う検証を選んでください。
すべてのリポジトリで同じ format・lint・type check・test・build を要求しないでください。
検証に cache・ログ・生成物が伴う場合は、出力先も許可範囲内か確認してください。
サーバーやブラウザを使用する場合は、許可された対象とテスト用データを使い、停止対象を今回起動したものに限定してください。

正常系だけでなく、今回関係する境界、非同期の完了順、保存失敗、取消、API・DB の整合性を確認してください。
再現が必要な場合は固定時間・固定入力・独立したテスト用状態を使い、偶然の結果や利用者の実データに依存しないでください。
新しいテストは、意味のある振る舞いや不変条件を検証する場合に追加し、実装をなぞるだけのものは作らないでください。

必要な検証が通った後は、新しい変更や未解決の懸念がない限り、同じ検証を繰り返しません。
無関係な既存不具合を独断で修正せず、今回の変更との関係を報告してください。
実施できなかった確認や、期待した失敗と予期しない失敗を区別してください。

### 完了報告

次を簡潔に報告してください。

- 受け入れ条件に対して何ができたか。
- 変更ファイルと目的。
- 実施した検証、その対象と結果。
- 未実施の検証、残件、今回止めた地点。
- 人間が判断・実施する必要がある操作。

ローカルの確認、CI、公開環境、実機や手動確認を混同しないでください。
学習用途では、教材の生成・検証と、学習者の理解・学習状況も区別してください。

引き継ぎが必要な場合は、既存のチャットや Issue に貼れる形で次を付けてください。
専用ファイルは依頼がなければ作らず、会話全文や計画を複製しないでください。

```text
対象・今回の工程：
現在の状態：branch、既存変更と今回の変更の区別、状態を確認した時点
実施済み／未実施：
重要な決定と参照先：
残件・次に読む場所：
次に必要な判断・許可：
```

commit・PR の文案を求められた場合だけ、目的別の変更、対象ファイル、検証結果を含めて作成してください。
既存の命名・文体・テンプレートを確認し、文案作成を staging・commit・push・PR 作成の許可へ広げないでください。
終了後に次フェーズ・次 Unit の準備や実装を自動で開始しないでください。
````
